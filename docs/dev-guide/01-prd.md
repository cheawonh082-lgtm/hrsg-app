# 1. 요구사항 → PRD.md

**목표:** 프로젝트 계획서를 개발 명세서(`PRD.md`) 하나로 바꾼다. 이후 모든 구현 프롬프트는 이 문서의 절(§) 번호를 가리킨다.

## 내가 입력한 프롬프트

① 명세서 작성 — 원문: [prompts/01-prd-request.md](prompts/01-prd-request.md)

```
# Task
아래 제공된 [프로젝트 계획서]를 바탕으로, 웹 프론트엔드/백엔드 개발을 바로 진행할 수 있는 상세한
**Markdown (.md) 형태의 개발 명세서(PRD 및 기술 설계서)**를 작성해 주세요.

## ⚠️ 중요 개발 요건
1. 계산 공식 및 실측 데이터 미확정 (Mocking 처리 필수) — 인터페이스 + Mock 함수로 모듈화
2. AI 수치 생성 금지 (가드레일) — 수치는 반드시 내부 계산기 결과로 응답 카드 생성
3. 보안 — 원문 파일, 고객사/발전소명, 사내 계산 공식 비노출

## 📄 [프로젝트 계획서 요약 정보]  (개요 · 도메인 배경 · 주요 기능 요건)
## 🎯 작성 요청 내용  (아키텍처·디렉토리 / 데이터 모델 / 화면별 UI·컴포넌트 / Mock 서비스·가드레일 / 4주 로드맵·검수)
```

② 반응형 요구 추가

```
md파일에 모바일/pc화면이 구현되며 레이아웃깨짐이 없도록 하는 구현기능을 추가해줘.
```

## 결과 요약
- 저장소 최상위에 `PRD.md` 생성 (약 1,100줄)
- 아키텍처: Vite + React + TypeScript 프론트엔드 ↔ FastAPI(Python) 백엔드, 로컬 실행
- 데이터 모델(`CalcInput`, `CalcResult`, 체크리스트, 챗 응답 카드), 화면 3개(계산기·챗·체크리스트) 명세
- `CalculatorService` 인터페이스 + `MockCalculator`, 나중에 `RealCalculator`로 교체하는 절차(§4.4)
- AI 가드레일: 숫자는 계산기 결과 카드에서만, 공식·원문·고객명 요청 차단
- 반응형(§3.4): 브레이크포인트 360~1920px, 모바일 바텀시트·드로어·하단 탭바, 가로 스크롤 금지
- 4주 로드맵: 1주차 골격 · 2주차 계산기 UI · 3주차 AI 챗 · 4주차 체크리스트·통합 검수
